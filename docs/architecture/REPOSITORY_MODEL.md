# PBOS Repository Model

## Separation of Concerns

The repository distinguishes four artifact classes:

### Canonical
Defines approved architecture and contracts.

### Operational
Represents active execution.

### Experimental
Represents hypotheses, prototypes, or unvalidated approaches.

### Evidence
Represents observed real-world results.

## Core Relationship

Canonical architecture governs implementation. Implementation produces evidence. Evidence may initiate discovery. Discovery may propose a canonical change only through the governed change protocol.

## Reference Implementation

The first real-world implementation is Ridz's own personal-brand ecosystem.

It is an implementation of PBOS, not a replacement for PBOS.
